## 一、命名方案

三组各自独立编号，序号三位补零；**只替换主文件名，原样保留扩展名**。

| 组别 | 目标格式 | 示例 | 编号依据 |
|---|---|---|---|
| 文档资料 | `2026_报告_001` + 原扩展名 | `2026_报告_001.docx` | 原文件名自然升序 |
| 代码备份 | `26版code_to001` + 原扩展名 | `26版code_to001.py` | 同上 |
| 日常杂物 | `2026日常之001` + 原扩展名 | `2026日常之001.jpg` | 同上 |

**编号顺序的判定规则**：脚本内 `files.sort()` 按文件名升序排列后依次编号，等价于资源管理器「名称升序」看到的顺序。因此人工逐张 F2 与脚本批量跑的编号结果完全一致，这也是两种条件可对比的前提。

## 二、脚本处理逻辑

`batch_rename.py` 的 `batch_rename(folder_path, prefix, start_num, padding=3)`：

1. 校验目录存在且为目录，否则直接返回、不改任何文件
2. 取文件列表时**排除隐藏文件与 `rename_log.txt` 自身**
3. `files.sort()` 后逐个 `os.rename()`，编号 = 起始号 + 序号，`zfill(3)` 补零
4. 目标名已存在则**跳过并记日志**（不覆盖）
5. 每次运行写入 `rename_log.txt`：处理时间、目录、总数、成功数、失败数、逐条「原名 → 新名 → 状态」

三组配置：

```python
{'folder': ..., 'prefix': '2026_报告_',  'start_num': 1}
{'folder': ..., 'prefix': '26版code_to', 'start_num': 1}
{'folder': ..., 'prefix': '2026日常之',  'start_num': 1}
```

## 四、输入是怎么来的

原始乱名样本在 10-21 之后已被改名，仓库内不再保留乱名副本，AI 侧一度**没有可跑输入**。本次按如下方式重建（全程只读 `samples/`）：

1. 每个样本文件**首行**保留了生成时的原名，格式为 `# 测试文件：<原文件名>`（由 `create_test_files.py` 写入）；
2. 逐文件读取首行，得到 30 个原名，与 `manual_timing_record.md`、`original_file_list.md` **逐一核对，30/30 完全一致**；
3. 在独立实验台目录内，把样本按原名**复制**成乱名件（`samples/` 原件一个字节未动）；
4. 记录每个乱名件的 SHA256，核对与样本件同源（不符数 = 0）。

清单留存：`ai/run_ai_20261025-173712_原始乱名清单.csv`（列：Folder / Now / Original / Hash）。
