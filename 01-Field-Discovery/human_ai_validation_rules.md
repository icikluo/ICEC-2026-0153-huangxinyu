# 人机校验规则：AI 批量重命名后的检查标准

## 一、校验目标

确保 AI 脚本完成批量重命名后，所有文件：
1. ✅ 文件名符合预期规则
2. ✅ 扩展名完整保留
3. ✅ 编号连续无重复
4. ✅ 无文件丢失或损坏

---

## 二、校验流程（5 步法）

### 第 1 步：检查日志文件（1 分钟）

```
□ 确认每个文件夹都生成了 rename_log.txt
□ 检查日志中是否有"失败"记录
□ 统计成功/失败数量是否匹配文件总数
```

**操作方法：**
```bash
# Windows 查看日志
type 文档资料\rename_log.txt

# 或使用文本编辑器打开
notepad 文档资料\rename_log.txt
```

---

### 第 2 步：抽查扩展名（2 分钟）

**抽样方法：**
- 每组随机抽取 3-5 个文件
- 重点检查特殊扩展名（如 .docx, .xlsx, .py）

**检查要点：**
```
✅ 正确：2026_报告_001.docx
❌ 错误：2026_报告_001（缺少.docx）
❌ 错误：2026_报告_001.doc（扩展名被截断）
```

**操作方法：**
```bash
# 列出所有文件及其扩展名
dir 文档资料\*.docx
dir 代码备份\*.py
dir 日常杂物\*.mp4
```

---

### 第 3 步：验证编号连续性（2 分钟）

**检查方法：**
```
□ 编号是否从 001 开始？
□ 编号是否连续（001, 002, 003, ... 010）？
□ 是否有重复编号？
□ 是否所有编号都补零（001 而不是 1）？
```

**快速验证命令：**
```bash
# 提取文件名中的编号并排序
dir /b 文档资料\* | findstr /R "[0-9][0-9][0-9]"
```

**人工核对表：**

| 编号 | 文档资料 | 代码备份 | 日常杂物 |
|-----|---------|---------|---------|
| 001 | ✅ | ✅ | ✅ |
| 002 | ✅ | ✅ | ✅ |
| 003 | ✅ | ✅ | ✅ |
| ... | ... | ... | ... |
| 010 | ✅ | ✅ | ✅ |

---

### 第 4 步：核对命名规则（2 分钟）

**规则对照表：**

| 文件夹 | 正确格式 | 常见错误 |
|-------|---------|---------|
| 文档资料 | `2026_报告_001.docx` | 漏写"报告"、下划线变横线 |
| 代码备份 | `26版code_to001.py` | 漏写"to"、大小写错误 |
| 日常杂物 | `2026日常之001.jpg` | "之"打成"知"、"1" |

**操作方法：**
```bash
# 查看文件夹中所有文件名
dir 文档资料\
dir 代码备份\
dir 日常杂物\
```

---

### 第 5 步：文件内容验证（1 分钟）

**目的：** 确保重命名后文件内容未被破坏

**抽样检查：**
```
□ 随机打开 2-3 个文件
□ 确认文件可以正常打开
□ 确认文件内容完整
```

**操作方法：**
```bash
# 尝试打开文件（Windows）
start 文档资料\2026_报告_001.docx
```

## 四、异常情况处理

### 情况 1：发现扩展名丢失

**处理方法：**
1. 记录所有受影响的文件
2. 检查原始备份文件夹
3. 重新运行脚本或手动修复

### 情况 2：编号不连续

**处理方法：**
1. 找出缺失的编号
2. 检查是否有文件被跳过
3. 查看 rename_log.txt 中的失败记录

### 情况 3：文件无法打开

**处理方法：**
1. 立即停止操作
2. 检查文件是否被损坏
3. 从原始备份恢复

## 七、人机校验规则总结

### 人工校验的必要性

| 原因 | 说明 |
|-----|-----|
| AI 可能漏处理 | 某些特殊文件名可能导致脚本跳过 |
| 环境差异 | 不同操作系统可能影响脚本行为 |
| 意外情况 | 文件被占用、权限不足等 |
| 最终把关 | 人类负责确认任务完成质量 |

### 人工校验的重点

1. **抽查而非全检**：AI 处理 30 个文件，人工只需抽查 10-15 个
2. **关注异常**：重点检查日志中标记为"失败"的文件
3. **快速验证**：使用命令行批量查看，而非逐个打开
4. **记录留痕**：校验过程和结果都要记录到报告中

### 人机协作最佳实践

```
AI 负责：批量执行、重复劳动、精确计算
人类负责：规则制定、异常处理、最终校验

效率 = AI 快速处理 (80%) + 人类快速校验 (20%)
```
