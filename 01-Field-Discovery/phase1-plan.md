## 课题 03：教学楼与宿舍无线信号盲区测绘

### 一、实验目标

- 测绘校园不同遮挡特征区域的无线信号质量
- 分析墙体材质、空间结构对 WiFi 信号衰减的影响规律
- 识别信号盲区并提出低成本优化建议

### 二、实验设计

#### 1. 采样点位（实际 9 个，超出要求的 8 个）

点位按**遮挡机理分层**选取，而非随机撒点：

| 编号 | 位置 | 楼层 | 遮挡特征 | 结构 / 材质 |
|---|---|---|---|---|
| P1 | 5 楼大厅 | 5F | 开阔无遮挡（**基准点**） | 玻璃幕墙 + 混凝土柱 + 吸音吊顶 |
| P2 | 露台 | 5F | 半开放，一侧临空 | 混凝土护栏 + 玻璃门 |
| P3 | 两楼连接处 | 5F | 半开放连廊 | 钢结构连廊 + 两侧混凝土墙 |
| **P4** | 5 楼厕所 | 5F | **多重阻挡 + 金属隔断** | 隔断板材 + 瓷砖 + 上下水管道 |
| P5 | 5 楼电梯口 | 5F | 走廊尽头转角 | 钢筋混凝土核心筒 + 钢板电梯门 |
| P6 | 8 楼电梯口 | 8F | 走廊尽头转角（**楼层对照**） | 核心筒 + 钢板电梯门 |
| P7 | 2 楼电梯口 | 2F | 走廊尽头转角（**楼层对照**） | 核心筒 + 钢板电梯门 |
| **P8** | 电梯运行中 | 5F→1F | **全金属封闭 + 运动** | 钢板轿厢 + 对重导轨 |
| **P9** | 2 楼电梯内部 | 2F | **全金属封闭 + 阻燃胶合板内衬** | 钢板轿厢 + 阻燃胶合板内壁 |

**设计要点**：
1. P1 为基准，其余点位与它相减得到净衰减；
2. **P5 / P6 / P7 是同类点位、三个楼层**，构成垂直对照，单独考察"楼层"这一个变量；
3. P7 与 P9 **同层、只隔一道电梯门**，用于隔离"金属屏蔽"这一个变量；
4. P3、P2（半开放）与 P4（深埋核心筒）构成"同楼层、不同封闭度"的对照。

#### 2. 测试指标

| 类别 | 指标 | 单位 | 采集工具 |
|---|---|---|---|
| **主指标** | 信号强度 RSSI | dBm | Wi-Fi 分析 App |
| 辅指标 | 下载 / 上传速率 | Mbps | 测速网 App |
| 辅指标 | 下行 / 上行延迟 | ms | 测速网 App |
| 辅指标 | 抖动、丢包率 | ms / % | 测速网 App |
| 连通性 | 是否可完成测速 | — | 测速网 App |

#### 3. 测试方法

- 每个点位**原地站立不动**，RSSI 读取 **4 次**，其中 **3 次同步完成测速**；
- RSSI 读数从**录屏截图**中逐帧读取，保证可溯源；
- 测不出的记「**未连接**」或「**无读数**」，**绝不填 0 或编造**；
- 每个点位拍摄**本人 + 手机 + 环境特征**的同框照，全部照片保留 EXIF 拍摄时间。

#### 4. 盲区判定口径

> **RSSI 均值 < −80 dBm → 盲区**
> App 无读数 / 测速无网络 → 重度盲区

### 三、实验执行过程（两轮）

| | 第一轮 2026-10-28 | **第二轮 2026-10-30（最终采用）** |
|---|---|---|
| 点位 | 8 个 | 9 个 |
| 主指标 | 下载速率 MB/s | **RSSI（dBm）** |
| 延迟 | ✗ 未采集 | ✓ 下行 / 上行延迟 |
| 抖动、丢包 | ✗ | ✓ |
| 判定口径 | < 1 MB/s（间接推断） | **< −80 dBm（课题原文）** |
| 数据位置 | `raw_data/03-wireless-signal-v1-20261028/` | `raw_data/03-wireless-signal/` |

**第一轮的问题**：所用测速 App 只输出平均速率，读不到 RSSI 也读不到延迟，只能用下载速率间接推断盲区，**与课题要求的"信号强度与延迟"不对齐**。

**第二轮的改进**：改用 `Wi-Fi 分析` App 直接读取 dBm，并用 `测速网` 取得延迟、抖动与丢包，判定口径回到课题原文的 −80 dBm。**本课题最终全部采用第二轮数据**，第一轮数据完整归档作为过程留痕。

### 四、实验结果

| 点位 | RSSI | 下载 (Mbps) | 延迟 (ms) | 判定 |
|---|---|---|---|---|
| P3 两楼连接处 | **−41.0** | 86.2 | **42** | ✅ 正常（最强） |
| P1 5 楼大厅 | −48.2 | 81.5 | 121 | ✅ 正常（基准） |
| P2 露台 | −53.8 | 109.4 | 66 | ✅ 正常 |
| P5 5 楼电梯口 | −65.5 | 74.8 | 353 | ✅ 正常 |
| P6 8 楼电梯口 | −71.0 | 70.0 | 378 | ⚠️ 临界 |
| P7 2 楼电梯口 | −71.0 | 23.6 | **794** | ⚠️ 临界（延迟最差） |
| **P4 5 楼厕所** | **−82.0** | 18.2 | 610 | ❌ **盲区** |
| **P8 电梯运行中** | 无读数 | 未连接 | 未连接 | ❌ **重度盲区** |
| **P9 2 楼电梯内部** | **−87.5** | 未连接 | 未连接 | ❌ **盲区** |

**三个关键发现**：

1. **厕所 −82.0 dBm 是"墙体类"盲区** —— 穿透多道隔断与金属管道，下载只剩大厅的 22%；
2. **电梯是"屏蔽类"盲区** —— 5 楼电梯运行中完全读不到 RSSI；2 楼电梯内部 −87.5 dBm，**有信号但测速三次全部失败**（"正在连接"→"节点连接失败"），是「有 Wi-Fi 图标、无业务」的教科书样本；
3. **信号达标 ≠ 体验达标** —— 2 楼电梯口 RSSI −71 dBm 按教材不算盲区，但延迟 794 ms、下载仅 23.6 Mbps，属**容量盲区**（与覆盖盲区是两种不同的病，解决手段也不同）。

## 课题 10：日常数字任务耗时审计与 AI 批处理实证

### 一、实验目标

- 识别一项高频重复性数字任务
- 对比人工处理与 AI 辅助处理的耗时差异
- 制定人机校验规则

### 二、任务选择（实际）

**任务：批量文件重命名**

| 项目 | 内容 |
|---|---|
| 任务频率 | 每周 2–3 次 |
| 样本规模 | 30 个文件，分 3 组，每组 10 个 |
| 3 组命名规则 | 文档资料 / 代码备份 / 日常杂物（三种不同规则） |
| 扩展名 | 11 种 |

> 原计划拟用"实验数据表格汇总"，实际改为**文件重命名**——抽样更容易、规则更贴近日常，且两种条件的起点可以做到完全一致。

### 三、实验设计

#### 1. 核心问题

> 把**前期准备、脚本生成、调试返工、结果校验**全部计入后，AI 是否真的比人工更快、更准？

#### 2. 计时口径

| 指标 | 定义 |
|---|---|
| `T_gen` | 从发出 Prompt 到拿到可用脚本 |
| `T_e2e` | 端到端总耗时（含返工与校验） |
| `T_human` | 人工逐张改名 + 校验的全过程耗时 |

#### 3. 对照条件

| 条件 | 操作方式 |
|---|---|
| 人工 | Windows 资源管理器逐张 F2 改名 + 计时 + 记录错误 |
| AI | 发 Prompt → 获取脚本 → 运行 → 报错返工 → 校验 |

两组**起点完全一致**：同名、同内容、同初始乱名。
