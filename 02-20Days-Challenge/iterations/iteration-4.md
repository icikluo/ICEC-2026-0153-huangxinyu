## 二、改进项一：CSV 编码自动识别

### 问题现象

| 用户 | 现象 |
|---|---|
| 用户 2 | "在 UTF-8 形式那里卡了很久，没接触过就不知道怎么改形式，后面问豆包的" |
| 用户 5 | 报错：`'utf-8' codec can't decode byte 0xd6 in position 0: invalid continuation byte` |

### 根因分析

```python
# 迭代 3 版本
df = pd.read_csv(csv_path, encoding="utf-8-sig")
```

**Excel 另存 CSV 时默认使用系统 ANSI 代码页（简体中文为 GBK/CP936）**，而程序硬编码按 UTF-8 解码：

- 中文在多数字节序列上 GBK 与 UTF-8 不兼容
- `0xd6` 在 GBK 中是"周"字的首字节，在 UTF-8 中是非法的延续字节
- 结果：直接抛出 `UnicodeDecodeError`，用户看到的是一串英文报错

### 修复

```python
def read_schedule_file(path):
    """兼容多种编码的 CSV，以及 Excel 原生 xlsx 格式"""
    if path.lower().endswith((".xlsx", ".xls")):
        return pd.read_excel(path, dtype=str)

    last_err = None
    for enc in ("utf-8-sig", "utf-8", "gbk", "gb18030", "utf-16"):
        try:
            return pd.read_csv(path, encoding=enc, dtype=str)
        except (UnicodeDecodeError, UnicodeError) as e:
            last_err = e
        except Exception:
            raise
    raise ValueError("无法识别课表文件编码，请另存为 CSV UTF-8 或 xlsx")
```

**改进点**：
1. 按优先级依次尝试 5 种编码，任一成功即返回
2. `utf-8-sig` 放首位，兼容带 BOM 的 Excel 导出
3. 只在**解码失败**时切换编码，避免掩盖其他读取错误
4. 全部失败时给出**中文提示**，而非英文堆栈

```python
if path.lower().endswith((".xlsx", ".xls")):
```

### 配套

- 文件选择器同时开放 `*.csv` 与 `*.xlsx` 两类过滤器

## 五、改进项四：课前 N 分钟二次提醒

### 问题

用户 7 提出：

> "建议添加功能课前二十分钟再次提醒"

### 场景分析

用户早上收到「全天课表」后，仍可能在下午临近上课时忘记——

- 早课：早上看到，不容易忘
- **下午课/晚课**：早上看到后经过数小时，容易忘
- 移动场景中（在食堂、图书馆）不便打开电脑查课表

### 方案

在「课表设置」中增加：

| 配置项 | 说明 |
|---|---|
| **启用课前提醒** | 复选框 |
| **提前分钟数** | 数字输入，默认 20 分钟 |

程序计算：

```python
for c in today_courses:
    remind_time = c["开始时间"] - timedelta(minutes=N)
    if now >= remind_time and c["开始时间"] > now:
        # 该课程即将开始，发送二次提醒
```

### 实现方式（用户版为手动运行，故采用"启动时检查 + 明确提示"）

用户版 exe 不能常驻后台，因此：

1. **发送测试时**，若已开启课前提醒，额外在日志区列出"今日最近的课前提醒时间点"
2. **提供「检查最近一次课前提醒」按钮**，用于手动确认哪些课程即将上课
3. 说明文档给出「Windows 任务计划」的配置方法，可定时唤醒程序检查

> 说明：真正无人值守的定时推送已由**作者自用的 GitHub Actions 版本**实现（每天 7:30 自动运行），
> 用户版定位为"按需检查"，两者互补。

### 关于 exe 打包的重要说明

**v1.1 采用 PyInstaller `--onedir`（文件夹版）而非 `--onefile`（单文件版）打包**，原因：

| 方式 | 现象 | 原因 |
|---|---|---|
| `--onefile` | 启动报 `Could not create temporary directory!` | onefile 需将自身解压到 `%TEMP%`，本机 Windows Defender 实时保护会拦截该行为 |
| `--onedir` | **正常运行** | 依赖文件直接放在目录中，无运行时解压，不触发拦截 |

**结论**：`--onedir` 更适合本机对抗杀毒软件误报，启动也更快。分发时需将整个文件夹打包（含 `_internal` 目录），不能只发 exe。

## 八、经验与后续

1. **真实用户反馈比自我评估更有效**：用户 2 和用户 5 独立遇到 GBK 编码问题，说明这是真实高频缺陷，而非个例。

2. **降低使用门槛要前置**：支持 xlsx 把一个技术门槛彻底消除。"在文档里写十遍'记得选 UTF-8'" 远不如 "支持直接读 Excel" 有效。

3. **UI 改进要有节制**：本次采用 Canvas 手绘圆角控件（约 400 行代码），未引入第三方 UI 框架，避免打包体积与兼容性问题。效果是统一了视觉语言，但保留了 tkinter 的轻量特性。

4. **打包方式要考虑实际运行环境**：`--onefile` 理论上更方便分发，但会被 Windows Defender 的启发式规则拦截；`--onedir` 虽然需要分发文件夹，但运行稳定。**工程决策应以"能跑起来"为第一优先级。**

5. **验证要覆盖真实数据**：首次用真实课表测试时发现「军训」占位行被误判为格式错误——这类问题只有用真实数据才暴露，造测试数据时容易遗漏。
