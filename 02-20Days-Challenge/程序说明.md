## 一、这个程序做什么

**一句话**：每天早上自动把当天的课表发到你的邮箱。

```
每天 07:30
   ↓
GitHub Actions 自动启动
   ↓
读取课表 → 算出今天第几周、星期几 → 筛选出当天的课
   ↓
拼成邮件正文 → 通过 QQ 邮箱发送
   ↓
把运行结果写进日志 → 自动提交回仓库
   ↓
你的手机收到「今日课表提醒」邮件
```

## 三、代码结构（253 行）

### 3.1 配置区（第 1-50 行）

```python
# 学期配置
SEMESTER_START = date(2026, 9, 7)   # 第 1 周的周一
MILITARY_WEEKS = {14, 15}           # 军训周，所有课停

# 时间配置（关键！）
BJ_TZ = timezone(timedelta(hours=8))  # 显式使用北京时间
```

**为什么必须写 `BJ_TZ`**：

GitHub Actions 服务器在 UTC 时区运行。若直接 `datetime.now()`，北京时间早上 7:30 在服务器上是前一天 23:30，**会把"星期四"算成"星期三"**，课程全错。

| 函数 | 行数 | 作用 |
|---|---|---|
| `load_dotenv_file()` | ~15 | 读取本地 `.env` 密钥 |

### 3.3 周次解析（最有意思的一段）

```python
def parse_weeks(cell):
    """'3;5-13;16-18' -> {3, 5,6,...,13, 16,17,18}"""
    weeks = set()
    for token in str(cell).split(";"):
        if "-" in token:
            a, b = token.split("-")
            weeks.update(range(int(a), int(b) + 1))
        else:
            weeks.add(int(token))
    return weeks
```

**支持的写法**：

| 写法 | 解析结果 | 含义 |
|---|---|---|
| `1-16` | `{1..16}` | 每周 |
| `3;6;9;12;17` | `{3,6,9,12,17}` | 每 3 周一次 |
| `3-13;16-18` | `{3..13,16..18}` | 两段 |
| `3;4-7;12-13;16;17;18` | `{3,4..7,12,13,16,17,18}` | 三段混合 |

## 四、安全性设计

| 风险 | 防护措施 |
|---|---|
| **密钥泄露** | 邮箱与授权码**不写在代码里**，从环境变量或 `.env` 读取 |
| **公开仓库泄露隐私** | 日志**只记课程数量**，不记课程名、教室、教师 |
| **日志中含邮箱** | 邮箱脱敏为 `3*********@qq.com` |
| **报错时泄露授权码** | `sanitize()` 函数检测并替换为 `***` |
| **`.env` 误提交** | 已加入 `.gitignore` |

## 九、常见问题

**Q：为什么用邮件而不是 App？**

每个学生都有邮箱，手机自带推送，不用装任何东西。做成 App 需要开发、上架、推广，成本高得多。

**Q：为什么用 GitHub Actions 而不是自己的服务器？**

免费、无需运维、自带日志。缺点是定时任务会延迟（本项目实际延迟 28~35 分钟）。

**Q：课表怎么更新？**

编辑 `schedule.csv` 并提交，下次运行就生效。

**Q：授权码和密码有什么区别？**

授权码是专门给第三方程序用的 16 位字符串，泄露后可以单独撤销，比直接用密码安全。
