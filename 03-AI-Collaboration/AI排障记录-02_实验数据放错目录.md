- **日期**：2026-10-23（错误自 10-13/10-14 起持续存在，10-21 扩大，10-23 发现）
- **环境**：VS Code + Qwen Code 扩展（后端 qwen3.5-122b），工程窗口标题为 `AI-lab`
- **错误位置**：`D:\AI-lab\ICEC-2026-0153-huangxinyu`
- **期望位置**：`D:\ICEC-2026-0153-huangxinyu`（课题文件夹直接放在 D 盘根下）

## 现象
1. 10-23 做课题 10「人工耗时实验」记录时，按聊天里 @ 的文件名打开文档，发现地址栏路径并不是预期的 `D:\ICEC-...`，而是多了一层 `AI-lab`。
2. 核对目录后确认：整个 ICEC-2026-0153-huangxinyu 课题树（01-Field-Discovery、02-20Days-Challenge、03-AI-Collaboration、README、.git）都建在了 `D:\AI-lab` 下面。
3. `D:\AI-lab` 里只有这一个课题文件夹，说明它不是原本规划的工作区，只是 AI 当时创建目录时顺手多建的一层壳。
4. 顺带暴露的第二个问题：AI 在 10-21 的会话里把错误结论也写进了这份放错位置的记录文件（详见排障记录 01 的 400 报错会话）。

## 根因
1. **AI 侧**：首次创建课题目录时，把"当前 VS Code 打开的文件夹"当成了"课题根目录"，直接在其下建 `ICEC-2026-0153-huangxinyu`，凭空多出一层 `AI-lab`。后续所有读写都沿用了这个错误根路径，越写越深，错误被固化。
2. **人侧**：10-13～10-21 期间只核对文件名和文件内容，没核对地址栏完整路径；文件名对得上，就默认位置也对得上。
3. **加重因素**：VS Code 标签页只显示相对路径（`@ICEC-2026-0153-huangxinyu/01-Field-Discovery/...`），从起点就省略了上层目录，肉眼看不出多了一层 `AI-lab`。
4. **不是数据损坏**：文件内容、大小、修改时间都正常，属于"位置错"，不是"内容错"，可以整体迁移修复。

## 处置方案（10-23 已执行/进行中）
1. **先盘点，不动手**。给 AI 的指令是："你把我的实验数据传错位置了，应该放在 `D:\ICEC-2026-0153-huangxinyu` 的，你现在先查 `D:\AI-lab` 里哪些数据要放回去，再让我决定做不做。" —— 让 AI 只出迁移清单，决定权留在人手里，避免它顺手把东西删了或覆盖。
2. **按清单分批迁移**，优先课题 10 相关的 `topic10_plan.md`、`manual_timing_record.md`（正在用、最要紧），再补其余 01 阶段文件、`phase2-plan.md`、`03-AI-Collaboration`、`README.md`。
3. **迁移用"复制后核对再删"**，不用剪切：先把文件复制到 `D:\ICEC-2026-0153-huangxinyu` 对应子目录，核对行数/大小一致后，再清理 `D:\AI-lab` 下的原件。
4. **`.git` 单独处理**（10-23 10:16 刚建的）。若新位置继续用 git，优先在新目录重新 `git init` + 首次提交，而不是搬旧的 `.git`，避免历史里记着一串错误绝对路径。
5. **迁移完成后重开工作区**：VS Code 直接打开 `D:\ICEC-2026-0153-huangxinyu`，不要再从 `D:\AI-lab` 进入，从源头断掉错误路径。

## 长期习惯（防复发）
- **每条 AI 指令开头钉死根路径**：写"所有文件只能读写 `D:\ICEC-2026-0153-huangxinyu` 下的路径，禁止新建上层目录"，不给 AI 自己推断工作目录的空间。
- **首次让 AI 建目录后，立刻核对一次完整绝对路径**（地址栏全选看一遍），这一步 10 秒，能省掉后面 10 天的返工。
- **不信任相对路径显示**：标签页、聊天引用里的 `@xxx/yyy.md` 都要能回答"它上面还有几层"。
- **VS Code 用"打开文件夹"直接指向课题根**，不要让一个通用的 `AI-lab` 壳目录长期当工作区。
- **重名目录是坑**：`03-AI-Collaboration` 同时出现在快捷访问区和课题内部，整理时优先消歧（改名或移出快捷访问区）。
- **配合 git 使用**：迁移到正确位置后，每天提交一次，路径或内容被改错时 `git diff` 能立刻暴露。
